## Verified findings

| ID | Priority | Finding | Evidence and acceptance |
| --- | --- | --- | --- |
| A1 | High | Out-of-band audio can appear as a valid guitar note | The production capture path at 48 kHz, fed 24,000 stereo float frames with a 0.9-amplitude 11,917.593111 Hz sine on the selected channel, reports 82.4079 Hz. `acceptSample` in `src/audio_capture.cpp` uses a one-pole low-pass followed by 12 kHz decimation. Add a resampler/anti-alias filter with a defined stop-band and regression cases around 12 kHz multiples. Keep B0 through E4 accuracy within an agreed tolerance. |
| A2 | Medium | The pitch hold can exceed 220 ms with sparse input | Acquire D3 using 18,000 frames at 48 kHz, then deliver 16 clean frames every 65 ms for eight ticks. The last valid estimate is 520 ms old and the displayed pitch remains about 146.841 Hz. The early return at `updateMeasurementsAt` for fewer than 120 new analysis frames skips `rejectPitch`. Expire the estimate by wall-clock time on every relevant branch. |
| A3 | Medium | Invalid stored numeric settings can disable correct readout | `MainWindow` loads three doubles with unchecked `toDouble()` and `std::clamp`. A Qt QVariant containing `nan` converts successfully to NaN and remains NaN after clamping. A corrupt calibration can make closestString return null while the UI retains a previous readout. A nonnumeric calibration converts to zero and clamps to 430 instead of restoring 440. Check conversion success and finiteness before applying range limits. Add startup coverage for corrupt legacy settings. |
| A4 | Low | The inclusive upper pitch boundary rejects a clean 700 Hz tone | A 4096-sample 12 kHz sine at exactly 700 Hz is rejected with the current 25–700 bounds. The interpolated estimate overshoots the strict upper-bound check in `src/pitch_detector.cpp`. Define a boundary policy and test both endpoints. This is outside the highest standard guitar open-string reference, but inside the adapter's stated analysis range. |
| A5 | Medium hardening | Archive symlink targets are compared but not confined to the package | `scripts/verify_preview.py` checks target equality, and `installer_payload.py` recreates it. Neither requires the resolved target to stay within the stage. Reject absolute/outside targets and resolve chains safely while retaining macOS framework links. Current artifacts are generated by trusted CI. An external attacker-controlled package exploit was not demonstrated. |

## Dependency maintenance finding

The shipped FFmpeg baseline is 7.1. As checked on 2026-11-08, upstream lists
7.1.5 as the latest 7.1 maintenance release and 9.0.2 as the latest stable
major release. Review the intervening security fixes against the exact shipped
configuration and Qt's supported FFmpeg build before 1.0.0; decide whether to
update the Qt/FFmpeg runtime. If updated, regenerate and verify matching
binaries, source bundle, hashes and notices. This is a maintenance review, not
a claim that the tuner exposes FFmpeg's media-decoding attack surface.
The tuner currently captures PCM with QAudioSource and does not expose a media
file/URL decoder. Reachability of these upstream issues through this application
was not established. See the [upstream security record](https://ffmpeg.org/security.html).

Qt 6.8's documented platform floors agree with the current installer thresholds
of macOS 12 and Windows 10 1809. Those thresholds still require product-specific
testing. See [Qt supported platforms](https://doc.qt.io/qt-6.8/supported-platforms.html).

The A1 probe uses a deliberately high-frequency synthetic signal. It demonstrates
alias rejection failure, rather than establishing its incidence with a real
guitar. A2 simulates degraded low-throughput delivery. A3 concerns corrupt or
externally edited settings. These input conditions belong in regression coverage
before the stable release.

  with an explicit macOS deployment target of 13.0.
- All four existing CTest cases passed, including capture and GUI preview.
- All nine Python tests passed. Python sources passed syntax parsing.
- Current documentation file links were checked.
- Synthetic production-capture probes at 12, 22.05, 44.1, 48 and 96 kHz correctly
  recognized B0, E2 and E4. The largest observed error in these 15 clean-tone
  cases was about 0.45 cent. This limited matrix does not cover plucks or noise.
- Core endpoint and capture probes reproduced A1, A2 and A4. A Qt conversion
  probe reproduced the NaN/invalid-text handling underlying A3.
- Temporary probe modifications were removed after testing.

No syntax or build failure was found in this environment. Existing test success
does not cover the newly reproduced cases. Windows execution, new live instrument
recordings, load profiling, sanitizer/fuzz runs and installer upgrade testing
were not performed in this review. PDF binaries were retained. Their content
was reviewed in the preceding documentation work and must be refreshed for 1.0.0.

      Use prerelease=false for the final stable GitHub Release.

      Attach verified installer checksums/manifests and matching source materials.
- [ ] Run final CI for the exact tagged source and publish those verified artifacts.

### Product decisions

Publisher certificates and notarization improve installation experience. Choose
and document the distribution policy for stable 1.0.0. An unsigned stable release
requires accurate approval instructions and acceptance of that user experience.

Manual target-string selection could help prevent tuning to the wrong octave,
but remains a feature choice. VST3, Linux installers, Intel Mac and Windows ARM
should remain separate milestones unless explicitly added to 1.0.0 scope.

The audio audit fixes and synthetic format coverage are complete. The next work
is hardware acceptance and performance/latency measurements, followed by the
FFmpeg maintenance decision and stable version/channel and release automation.


## Implementation follow-up

The first fix batch implements A1–A3. Capture now applies an eighth-order
Butterworth low-pass before decimation, and sparse input enforces pitch expiry.
Numeric settings require successful conversion and a finite value before range
clamping. Regression coverage includes the previously failing out-of-band tone,
clean B0/E2/E4 and alias-band tones across five capture rates, the 520 ms sparse
input case, and corrupt/valid legacy numeric settings.

These fixes passed all four local CTest cases using Qt 6.11.2. A4 and A5 remain
open. Real-instrument and performance acceptance remain required for 1.0.0.


## Second fix batch

A4 now has a documented 5-cent endpoint fringe, with accepted estimates clamped
to the requested interval. Lag search extends beyond the endpoints so that
outside tones can be rejected instead of producing an artificial edge minimum.
A5 uses shared lexical path/link validation before archiving, ZIP verification
and installer-stage copying. It rejects escapes, cycles and inventory entries
under symlink parents while accepting the published framework layout.
A6 saturates the readiness counter at 120 analysis frames during closed-gate
capture as well as ordinary measurement.

All four local Release CTest cases and 12 Python cases pass. A1–A6 regression
coverage now passes locally. Hardware and final release acceptance remain open.
